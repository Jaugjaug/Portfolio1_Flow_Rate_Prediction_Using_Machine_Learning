## 🔎 Overview

This project selects 20 medium-sized watersheds (100–5,000 km²) based on **CAMELS** attributes, downloads their daily streamflow data from the **USGS** service, builds explanatory features (seasonality + lagged streamflow), then trains two regression models (**Random Forest** and **XGBoost**) to predict streamflow. Results are then explored through an interactive **Streamlit** app.

The computation pipeline (download + training) and the visualization app are deliberately kept separate: the app never recomputes anything itself, it reads the files already produced by `pipeline.py`, which makes browsing near-instant.

## ✨ Features

- Reproducible watershed selection via a fixed seed
- Automated download of streamflow data (USGS Water Data API)
- Feature engineering: cyclical encoding of day-of-year (sin/cos) + lagged streamflow (1-day and 7-day lags)
- Training of two models (Random Forest, XGBoost) with a temporal train/test split
- Standard hydrological metrics (NSE, KGE, RMSE, PBIAS, R², MAE)
- Interactive dashboard: time series, observed-vs-predicted parity plot, residuals, flow duration curve
- Common time-coverage check across watersheds
- Ability to re-run the pipeline directly from the interface, with a progress bar

## 🚀 Usage

### Run the application

```bash
conda activate venv_streamflow
cd .\Folder\Of\The\Repo\
streamlit run app.py
```

On first launch, no data has been computed yet: click **🔄 Run / recalculate the pipeline** in the sidebar (or run the pipeline from the command line, see below). This initial computation downloads ~20 years of daily streamflow for 20 watersheds and then trains both models; expect this to take several minutes depending on your connection. Switching watersheds afterwards is then instantaneous, since the app only reads already-computed files.

## 🔬 Methodology

1. **Watershed selection** (`select_basins`) — filters CAMELS watersheds whose area (`area_gages2`) is between 100 and 5,000 km², then samples 20 of them using a fixed seed (reproducibility).
2. **Streamflow download** (`download_streamflow`) — queries the USGS service (parameter `00060`, statistic `00003` = daily mean) for each watershed between 2000 and 2020.
3. **Feature engineering** (`engineer_features`) — cyclical encoding of day-of-year (`doy_sin`, `doy_cos`) and streamflow lagged by 1 and 7 days (`flow_lag1`, `flow_lag7`).
4. **Training** (`train_and_evaluate`) — temporal split (training before January 1, 2017, testing after), training of a `RandomForestRegressor` and an `XGBRegressor` with one-hot encoding of the watershed as an explanatory variable.
5. **Evaluation** (`metrics_utils.metrics_table`) — metric computation per watershed × period × model.

## 📊 Evaluation Metrics

| Metric | Description |
|---|---|
| **NSE** | Nash–Sutcliffe Efficiency — standard hydrology measure of model fit |
| **KGE** | Kling–Gupta Efficiency — decomposes correlation, bias, and variability |
| **RMSE** | Root mean squared error (cfs) |
| **PBIAS** | Percent bias (>0 = overestimation, <0 = underestimation) |
| **R²** | Coefficient of determination |
| **MAE** | Mean absolute error |

The qualitative NSE interpretation (`quality_flag`) follows the indicative thresholds from Moriasi et al. (2007), *Model evaluation guidelines for systematic quantification of accuracy in watershed simulations*, Transactions of the ASABE, 50(3), 885-900.

## 🗂️ Data Sources

- **CAMELS** (Catchment Attributes and MEteorology for Large-sample Studies) — only the `camels_topo.txt` file (topographic attributes, a few hundred KB) is used, to select watersheds and retrieve their USGS site IDs. This is not the full CAMELS-US dataset (which also includes daily meteorological forcing data for ~670 basins, spanning several GB). Available from the [NCAR/UCAR website](https://ral.ucar.edu/solutions/products/camels).
- **USGS Water Data API** — daily streamflow series are downloaded directly from the USGS service via the [`dataretrieval`](https://github.com/DOI-USGS/dataretrieval-python) library, not from CAMELS.

## ⚠️ Known Limitations

- The file `data/camels/camels_attributes_v2.0/camels_topo.txt` is not included in the repository (must be downloaded separately, see above) and must be placed manually in the expected directory structure.
- The USGS download introduces a 1.5 s pause per watershed to respect API rate limits; the initial computation can therefore take several minutes.
- Model hyperparameters are hardcoded in `pipeline.py` (no hyperparameter search).
